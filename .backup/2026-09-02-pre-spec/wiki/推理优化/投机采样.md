# 草稿模型：给大模型配置一个草稿（draft）模型，草稿模型负责字符生成、大模型（target）验证生成结果。
 **speculative decoding（推测式解码）**：用小模型“先猜”，大模型“一次验”**
1. 用一个更小的 **draft model（草稿模型）** 按常规自回归方式先“猜”出接下来 γ  **个 token**；
2. 再让原始的大模型（Original LLM）对这串猜测进行**验证**，验证只需要**一次 forward**。
如果草稿模型在这 个 γ token 里有α **个** **token** 猜对了，那么原始大模型的一次 forward 就等价于“确认”了α **个 to****ken**，并且还能再生成 **下一个 token**，也就是 **一次 forward 产****出 α+1** **个 to****ken**，从而达到加速效果。
在这个框架里，**草稿模型和原始大模型做的是同一件事**——给定当前 token 序列，预测下一个 token。想用一个**参数规模小很多**的模型把这件事做好非常困难，往往导致效果不理想（命中率不够高、收益被稀释）。
另外，草稿模型是**独立预测**，并没有利用原始大模型在推理过程中已经抽取出来的、非常丰富的语义信息，这也会带来潜在的效率损失。

# 辅助层：在大模型基础上增加一些头层，使其能生成更多的字符，如Medusa、EAGLE、MTP等。
## Medusa：
- 首先生成各个位置的候选token；MEDUSA通过接在原模型的多个解码头来获取多个位置的候选token
- 把各个位置的候选token进行处理，选出一些候选序列，进行验证；MEDUSA通过tree attention来处理
- 最后通过typical acceptance选择最终输出的结果
![[specdec-medusa-heads.png]]
## Eagle1：**直接利用原始大模型已经计算出来的上下文特征（contextual features）**。具体来说，在原始模型预测下一个 token 的过程中，会自然产生倒数第二层（second-top layer）的输出特征向量——这些特征**不需要额外计算**，我们可以直接拿来用。
EAGLE 的 draft model 由三块组成：Embedding layer、LM Head、Autoregression Head。Embedding layer 和 LM Head **直接复用 target LLM 参数，不需要训练**；训练的主要是 Autoregression Head。
1.在原始大模型（Original LLM）执行一次 forward 的过程中，我们会收集它倒数第二层（second-top layer）输出的特征向量（features），构成**特征序列**：(bs, seq_len, hidden_dim) 。并结合这次 forward 由原始 LLM 生成的一个 token，构成**shifted token 序列** ：(bs, seq_len)。
2.将以上作为输入：特征序列 (bs, seq_len, hidden_dim) + shifted token 序列 (bs, seq_len)
3.将shifted token → embedding，然后与 feature 拼接成 (bs, seq_len, 2×hidden_dim)
4.接着，以这些特征为起点，**FeatExtrapolator（特征外推器）**开始进入“猜测（guessing）”阶段。
5.FeatExtrapolator 以自回归方式预测下一个特征向量。随后，我们使用原始模型中冻结的 LM head 来得到 token 的概率分布，并从该分布中进行采样生成 token。
![[specdec-eagle1-feat-extrapolator.png]]
通过多次重复：“预测特征 → LM head 得到 token 分布 → 采样 token”的过程，我们可以形成一种类似树状（tree-like）的生成过程，如下图所示。
![[specdec-eagle1-draft-tree.png]]
在图中的示例里，FeatExtrapolator 只用了 3 次 forward，就“猜”出了一个包含 10 个 token 的树状候选序列。
## Eagle2:主要改进是把“固定形状的静态 draft tree”换成“基于上下文动态调整的 draft tree”，并取得了比 EAGLE-1 快 20% 以上的效果。
## Eagle3:**直接移除Lfea损失  ,让 draft 不再必须拟合 target 的 top-layer feature，而是更直接地服务于“猜 token”，从而释放模型容量，让“加数据”真正能转化为更高的 Step 1 接受率。**
![[specdec-eagle3-multilayer-fusion.png]]
## MTP:将大模型原始的1-token的生成，转变成multi-token的生成，从而提升训练和推理的性能。具体来说，在训练阶段，一次生成多个后续token，可以一次学习多个后续位置上的label，进而有效提升样本的利用效率，提升训练速度；在推理阶段通过一次生成多个后续token，实现成倍的推理加速来提升推理性能。

## Dflash：![[specdec-dflash-arch.png]]
**1) 特征融合（Feature Fusion）**
在 **prefill**（首次前向、建立上下文）或 **verification**（目标模型验证草稿）之后，我们从**目标模型（target）**中提取隐藏层特征（hidden features），并对这些特征进行融合处理（fuse）。
直观理解：目标模型刚算完一轮，它内部“已经理解了上下文并形成了高质量表征”，DFlash 直接把这份“理解”提取出来作为草稿生成的强条件信息。
**2) 条件注入（Conditioning）**
这些融合后的特征会被**直接送入草稿模型各层的 Key/Value 投影（K,V projections）**里，并缓存到草稿模型的 **KV cache** 中。
这句话非常关键：
- 不是简单把特征拼到输入 embedding 上；
- 而是更“注意力机制友好”的注入方式：直接影响 draft 模型注意力的 K/V（也就是“它该关注什么、如何组织上下文信息”）。
- 这样 draft 在生成时就能以目标模型的表征为“导航”。
**3) 并行起草（Parallel Drafting）**
在上述“富上下文条件”（rich context）以及**最后一个已验证 token** 的条件约束下，草稿模型用扩散方式**并行预测下一段 token block**（比如一次预测一个 block）。
你可以把它理解为：
- 自回归 drafter：下一 token、再下一 token……串行写草稿；
- DFlash drafter：一次性把“下一段”草稿并行写出来，然后交给 target 去验收。
**4) 降低开销的工程策略（Minimize overhead）**
为了把额外开销压到最低，DFlash 做了两个很实用的设计：
1. 草稿模型**复用**目标模型的 **embedding 层**和 **LM head（输出头）**
- embedding：把 token 映射到向量空间的那层
- LM head：把隐状态映射回词表 logits 的那层 这样能省参数、减显存、也减少训练/部署复杂度。
2. 只训练中间层（intermediate layers）也就是说，draft 模型主要学的是“怎么在注入了 target 特征后，快速把中间表征变成可用的下一段 token 分布”。**
作者最终把 draft 的层数设为 **5 层**，理由是：在“草稿质量（接受率）”和“生成速度（drafter 成本）”之间取得一个折中。
## Dspark
（Dflash的问题是缺少序列感知能力）**保留 DFlash Backbone 不变，仅通过两个轻量级辅助模块，补齐其最薄弱的序列依赖环节**。整个模型仍维持一次 Forward 完成块级预测的能力，仅在输出 Draft Logits 之前，新增两个模块：
- • **Markov Logit-Bias Head**：利用前一个 Token 修正当前预测
	- Markov head：**一阶马尔可夫假设**。预测当前位置 k 的下一个 token，只需要考虑**前一个位置的 token (xk−1​)**，而忽略更早的历史信息。这大大简化了问题。![[Pasted image 20260901140243.png|545]]
		- **输入**: 前一个 token 的索引 xk−1​。
		- **W1​ (Embedding Lookup Table)**: 这是一个大小为 V×r 的矩阵，其中 V 是词表大小，r 是一个较小的维度（文中默认为 256）。通过查找操作 `W₁[xₖ₋₁]`，我们可以从该矩阵中取出与前一个 token 对应的嵌入向量，得到一个 r 维的向量。这相当于把离散的 token ID 转换成了一个连续的稠密向量表示。
		- **W2​ (Logit Projection)**: 这是一个大小为 r×V 的矩阵。它将上一步得到的 r 维嵌入向量投影回 V 维空间。
		- **B(xk−1​,⋅) (Transition Bias)**: 最终输出的结果是一个长度为 V 的向量。这个向量的每一个元素可以看作是对应下一个可能 token 的“偏好分数”或“偏置项”。这个向量会被加到模型的原始 logits 上，从而影响最终的预测概率。
	- RNN head：维护循环状态 Sk，累积块内完整前缀历史。通过门控更新整合前状态、前 token 嵌入和 backbone 隐藏状态。在长块上略优于 Markov head，但实现更复杂。
	            ![[Pasted image 20260901151712.png|408]]![[Pasted image 20260901140326.png|612]]
- • **Confidence Head**：预估每个 Draft Token 被接受的概率
	- 对每个 draft 位置 k 输出标量估计  ，表示"给定前面所有 token 已被接受的前提下，当前位置 token 通过验证的条件概率“
	      ![[Pasted image 20260901135843.png]]
	- 训练：通过L1 loss来训练（L1 距离最大值为 2（当两个分布完全对立时），除以 2 后范围变成 [0,1]，方便后续计算）越相似loss越小
	      ![[Pasted image 20260901135945.png]]
这两个模块带来的额外计算开销极低，却能显著提升整体接受率。

## Dflash2(2026.8.18): Keep Drafting Parallel
![[Pasted image 20260831135404.png|700]]
问题1：DFlash 并行地独立预测每个位置。每个预测本身都合理。然而，它们之间缺乏逻辑联系，因此在验证阶段，不连贯的预测块会被截断。
分析1：Flash的首选词准确率高达85.4%，但正确的词条有99.5%的概率出现在其前16个候选词条中。即使首选词条错误，正确的词条通常也在列表中。![[Pasted image 20260831161113.png]]
如果有一个预测系统总能从前 16 名候选人中选出最合适的人选，那么接受长度将从 4.27 增加到 6.79 。
![[Pasted image 20260831161532.png]]
解决方案1：
1. 每个位置保留 top-16 token；
2. 评估相邻位置候选 token 的兼容性；
3. 从候选空间中选出一条连贯路径。
![[Pasted image 20260831161637.png]]
- Ut(b)：原始b DFlash 对候选  给出的 logit；
- A(a) ：前一个 token 的低维 embedding；
- B(b)：当前 token 的低维 embedding；
- H(h)：由当前位置 hidden state 产生的上下文门控；
问题2： 上面表格的召回率在区块末尾均有所下降。即使选择完美，准确率仍然会从第一个位置的 99.5% 下降到最后一个位置的 87.8%。任何选择器都无法解决这个问题，因为候选集本身质量也在变差，这种现象称为后缀衰减。
分析2：五层主干网络可能太小，无法维护模块间的依赖关系。但是增加深度，参数量增加；而且在 block 前部也增加计算，前部本来就没有太大问题
![[Pasted image 20260901141617.png]]
解决方案2：block 越靠后的位置越不准。DFlash 2 给出的解释是：attention 分配给 block 内部依赖的比例随层数快速衰减——Layer 1 有 30%，到 Layer 5 只剩 8%。深层 attention 都跑去看长上下文了，block 内部"后面几个 token 该怎么接前面几个"这件事没人管。所以设计一个专门的模块来处理块内的工作。
![[Pasted image 20260901141656.png]]
在每个 attention 和 MLP 前后插入 two-tap dynamic depthwise conv。"dynamic" 指卷积系数不是纯静态的——由一个学到的 base kernel 加上一个从当前 hidden state 算出的 correction 组成，且每 16 个 channel 共享一个 correction（这是参数量能压住的关键）。
![[Pasted image 20260831175711.png]]
![[Pasted image 20260831171327.png]] 
只看前一个，最紧的依赖就在相邻之间，不用搜远的；而且层层堆叠之后，感受野自然会扩张。
其中卷积系数并不是完全固定的：

- 包含一个学习得到的基础 kernel；
- 再加上由当前 hidden state 计算的动态修正；
- 每16个通道共享一组修正参数。

# 数据匹配：利用历史数据/模板，通过规则匹配的方式生成字符，然后用大模型进行校验，如ngram、suffix decoding。
## **Ngram**（gram指代元组)：是一种基于历史数据进行概率计算并获得预测结果的方式。其核心的思想是：一个词出现的概率依赖于它前面的 N-1 个词。
在推理中应用Ngram方法，一般步骤：
- 确定匹配长度、预测长度。
- 根据已有数据(prompt或者历史数据)构建Ngram词表。
- 用主模型验证结果，若满足则接受，反之亦然。
## **Suffix decoding**尾缀匹配：根据输出数据来构造尾缀树，匹配到合适的尾缀后选择得分最高的值作为输出，得分的高低与数据出现频率相关。suffix decoding涉及有两个关键参数：窗口大小P、后缀节点数量N。结合下图示例（P=2, N=3），输入为“85485”，suffix decoding匹配的头有两种“5”和“8，5”。
其基本步骤：
1. 根据保存的历史数据，构造第一个后缀树。
2. 根据**当前输出**构造的另一个后缀树。
3. 找出两棵后缀树中满足要求的子树。
4. 对子树进行打分排序，挑选出分数最高的子树。
5. 用LLM验证子树的值是否满足要求，若满足则接受。
