# Share Note（笔记对外分享）

把一篇笔记变成**一个可以直接当附件发出去的文件**。

## 为什么需要这个 skill

笔记里的图片用的是 Obsidian 短链 `![[xxx.png]]` —— 这是 **vault 内部的检索语法**，文件一旦离开 vault
就没有任何程序解析得了它。直接把 `.md` 发给别人，对方看到的是一堆死链接，图全没了。
所以分享不能靠"复制文件"，只能靠**导出成自包含格式**。

## 铁律

1. **不改 vault 任何内容。** 不动源笔记、不动 `index.md`、不动 `log.md`、不动 `raw/`、不动 `assets/`。
   这是纯导出型 skill，唯一产物是 `_export/` 里的文件。
2. **产物只进 `_export/`**，该目录已在 `.gitignore` 里 —— 导出不污染仓库、不进 git 历史。
   脚本每次会自检这一行还在不在，报警了就去 `.gitignore` 补上 `_export/`。
3. **一次只回答"发哪个文件"**，别让用户自己在两个产物之间猜。

## 步骤

### 1. 跑脚本，别自己拼转换命令

```bash
python .claude/skills/share-note/scripts/export_note.py "<笔记名或路径>"
```

笔记名可以只给片段（`投机采样`），脚本会在 `wiki/` 下按文件名检索；也可以给完整路径。
可以一次给多篇。`--html-only` 跳过 PDF。

脚本已经把易错的部分固化了：

- vault 根目录自动识别，图片按 Obsidian「全库按文件名检索」的语义解析，和你在 Obsidian 里看到的一致；
- 图片转 base64 内嵌，**单文件离线可读**，不依赖 `assets/`；`![[图.png|540]]` 的宽度参数照样生效；
- **CJK 粗体修正**：标准 Markdown 解析器不认「中文标点 + `**` + 中文字」这种收尾（Obsidian 宽松），
  例如 `**草稿模型（draft）**按常规…` 会漏成裸星号。脚本单独处理了这一类，代码块/行内代码不受影响；
- **摘掉仓库内务小节**：`## See Also` 和 `## 备注` 默认**不导出**。前者指向的是对方根本拿不到的
  笔记，后者记的是本库的加工历史 —— 单独发出去只会干扰阅读。按标题级别界定范围（遇到同级或更高级
  标题即止），代码块里的同名行不受影响；确实要留就加 `--keep-internal`；
- **源笔记体检**：导出前扫一遍落单的反引号和多余/未收尾的代码围栏（退出码 5），**只报告，不改源笔记**；
- `[[其它笔记]]` 双链降级成灰色纯文本（目标笔记不在导出范围内），不会变成死链；
- 表格横向滚动、深浅色跟随系统、手机宽度自适应、打印分页避免切图切表；
- PDF 由本机 Edge/Chrome 无头渲染，找不到浏览器就只出 HTML。

### 2. 看退出码

| 码 | 含义 | 你该做什么 |
|---|---|---|
| 0 | 全部成功 | 往下走第 3 步 |
| 1 | 笔记没找到 / 片段匹配到多篇 | 脚本已列出候选，**问用户是哪一篇**，别自己挑 |
| 2 | 有缺图（产物仍生成了） | 正文里缺图处已标红。把缺的文件名报给用户，多半是 `assets/` 里被改名或漏迁 |
| 3 | 没找到浏览器，PDF 跳过 | HTML 可用。告诉用户装 Edge/Chrome，或设 `BROWSER_FOR_PDF` 指向浏览器 |
| 4 | 缺 mistune | 让用户 `pip install mistune` |
| 5 | 源笔记有落单的反引号 / 多余围栏 | 产物已生成，但**从那行往后会错位**。见下面「源笔记体检」 |

### 3. 汇报：直接告诉用户该发哪个

| 产物 | 适合 |
|---|---|
| `.html` | 发文件给同事，浏览器双击即开，离线可读、自适应手机、跟随系统深浅色 |
| `.pdf` | 微信 / 邮件，手机预览最稳，不会被当成可疑文件拦 |

汇报里带上：图片张数、两个产物的大小和 PDF 页数、摘掉了哪些内务小节、缺图（若有）、降级成纯文本的双链有哪几个。
**别复述脚本的全部输出**，用户只关心"能不能发、发哪个"。

## 源笔记体检（退出码 5）

Obsidian 的解析比标准 Markdown 宽松得多，所以源笔记里有些错**在 Obsidian 里看着好好的，
一导出就现形**。而且这类错的共同特征是 —— **坏的是后半篇**，扫一眼开头根本看不出来：

| 脚本报的 | 实际后果 | 常见成因 |
|---|---|---|
| 反引号落单 | 那行往后所有行内代码的配对整体错开一位，正文里冒出 `</code>xxx<code>` 这种倒转 | 收尾打成了中文引号 `‘` `’` 或半角 `'` |
| 这道围栏是多余的 | 本该是正文的几行被吞成一整块代码 | 上一段代码块收尾后多留了一行 `` ``` `` |
| 围栏没有收尾 | 从那行起整篇都变成代码 | 只写了开围栏 |

注意第二种：围栏**数量是偶数、也能正常配对**，靠数 `` ``` `` 查不出来 —— 带语言标记的 `` ```bash ``
按 CommonMark **不能**当收尾围栏，所以它会被上一道落单围栏一起吞进去。

**处理方式：报给用户，问他要不要改，别自己动手。** 源笔记归用户，这个 skill 的铁律第 1 条是只读。
报的时候给行号 + 那行原文 + 一句「改哪个字符」，用户点头了再改（那已经是 normalize 的活，不是 share 的活）。

## 对方要接着编辑，而不只是阅读

单文件 HTML/PDF 是只读形态。若用户说对方要**改**这篇笔记，改用 zip 方案，并**明确问过用户再做**：

- 复制一份 md 到临时目录，把 `![[x.png]]` 改写成标准相对路径 `![](assets/x.png)`；
- 只挑这篇实际用到的图进 `assets/`，不要整个目录；
- 打包成 zip。这样 Typora / VSCode / 上传 GitHub 都能直接用。

源笔记本身**仍然不动** —— 改写只发生在临时副本上。

## 注意

- `See Also` / `备注` 已由脚本自动摘掉，但**正文里的自用批注摘不掉** —— 比如 `> ⚠️ 存疑`、
  「这个数不能用」、指向别篇笔记的 `[[xxx]] §2.9` 交叉引用。导出前扫一眼，
  发现这类内容就提醒用户一句「这段是你自己的存疑批注，要不要我导出前先摘掉」，由用户决定，别擅自删。
- 笔记体量大（几十张图）时 HTML 会到 5–10 MB，属正常，微信/邮件都发得动；真嫌大再考虑压图。
