# Daily Report（学习日报）

把用户当天记在 `wiki/` 里的学习笔记，压缩成**几句话的中文日报**，直接在对话里给出。

## 铁律

1. **绝不写文件。** 不新建日报文件、不改 `index.md`、不追加 `log.md`。这是纯输出型 skill，唯一产物是对话里的那段话。用户若说"存一下"再另行处理。
2. **只写用户真学过的。** 日报是给用户交差用的，写进去的每一句他都要能对答。宁可少写，不可多写 —— 见下面的「反臆造」。

## 步骤

### 1. 找出当天改动

跑本 skill 自带的脚本，别自己拼 git 命令：

```bash
bash .claude/skills/daily-report/scripts/collect_diff.sh "<vault根>"
```

不带参数 = 今天 0 点至今、逐文件列出全部新增行，正是日报要的。
（同一个脚本还有 `--days N --digest` 汇总模式，那是给 [`weekly-report`](../weekly-report/SKILL.md) 用的，写日报别用。）

脚本已经把易错的部分固化了：只看 `wiki/`、中文文件名不乱码、工作区改动 + 当天 commit 合并成一份净 diff、
按文件分段、每文件截断到 120 行且**显式报告剩余多少行**、绕开本 vault 定时自动备份提交造成的竞态。

**退出码**：

| 码 | 含义 | 你该做什么 |
|---|---|---|
| 0 | 有改动，已输出 | 往下走第 2 步 |
| 1 | 今天 `wiki/` 无改动 | **别猜**，直接问用户今天动了哪篇 |
| 2 | 不是 git 仓库 / 没有 `wiki/` | 报错给用户，别硬来 |

看到「剩余 N 行未显示」而这篇恰好是今天的主线时，用 `MAX_LINES=400 bash ...` 重跑一次拿全。

> 这个 vault 每隔几分钟自动 commit 一次（`vault backup: <时间戳>`）。脚本取的是「今天 0 点前最后一个提交
> → 当前工作区」的**净 diff**，已经把这些自动提交合并掉了，所以你看到的每个文件就是它今天的完整增量，
> 不会被撕成十几段。**不要按 commit 数量估工作量。**

### 2. 读懂新增内容

脚本给的每一段都是**某文件今天新增的行**。据此提炼：学了哪个主题、具体到哪些子模块/概念、哪块明显是重点。

判断重点看**新增行的体量和质地**：某文件新增 186 行且有展开论述 → 今天的主线；只加了 1 行索引条目 → 不是学习内容。

跳过这几类噪声，它们不是「学习」：
- `wiki/index.md` —— 索引条目，只说明某篇动过，本身无内容
- `wiki/log.md` —— 我自己写的操作日志，**绝不能拿来当用户的学习成果**
- 只改了错别字、排版、链接路径的片段

### 3. 写日报

**长度**：3–5 句，一段。不分小标题、不加 markdown 列表、不用表格。

**结构**（固定顺序）：
1. 今天研究了什么（大方向 + 承接昨天的话就点一句"继续/按昨天的计划"）
2. 具体看了哪几块（点到子模块、函数名、概念名，这是日报的干货）
3. 顺带了解的次要内容（用"顺带""另外"带过）
4. 明天的计划（见下）

**语气**：平铺直叙的第一人称流水账，和用户昨天那份保持一致。不用"深入探索""收获颇丰"这类总结腔。

**参考范本**（用户认可过的成品）：

> 今天继续研究 sglang 的 scheduler 源码，重点看了 get_next_batch_to_run 和 run_batch 两个子函数。组批这边看了 prefill 优先逻辑和等待队列的几种优先级调度策略（FCFS、LPM 等），顺带认识了 RadixCache 这个复用公共前缀 KV 的数据结构；run_batch 这边学习了 forward 的调用链和采样环节，包括 Greedy、Temperature、Top-K、Top-P 等采样方法和约束采样，也顺带了解了注意力 backend 的选型。另外把 Detokenizer 的 event_loop 过了一遍，难点在增量解码和 UTF-8 半字符边界处理。明天详细研究 RadixCache 和 AttentionBackend 的实现。

### 4. 明天的计划

按优先级取：
1. 用户在本轮对话里说了明天干什么 → 照写
2. 笔记里有明确的"待办/下一步/TODO" → 用它
3. 都没有 → 从笔记的自然延续推一个（如笔记里写了"先读 normal 再看 overlap"），**并在日报外面说明这句是推的**，让用户好改

## 反臆造（最容易翻车的地方）

用户对日报的准确度要求很高 —— 他曾明确纠正过"我并没有研究 KV 缓存部分，只是知道了 RadixCache 这个数据结构"。**深度必须如实反映**：

| 笔记里的痕迹 | 日报里该怎么说 |
|---|---|
| 大段展开、有细节和自己的理解 | 「重点看了 X」「详细研究了 X」 |
| 只有一两句、列了个名词 | 「认识了 X」「顺带了解了 X」 |
| 只出现在表格/清单里 | 「过了一遍」，或干脆不写 |

- **别把"知道名字"写成"研究了"**，别把"顺带看到"写成"重点学习"。
- **别替用户扩写他没写的东西** —— 你知道但笔记里没有的，不许加。
- 拿不准某块该算"重点"还是"顺带"，**按轻的写**，然后在日报外面问一句。

## 输出格式

- 日报正文用 **blockquote**（`>`）包起来，方便用户整段复制。
- 正文之外可以补一两句说明：比如「明天的计划是我推的」「X 我按『顺带』写了，如果你其实钻得挺深就告诉我」。
- 说明不要长，别喧宾夺主。

## 用户追改时

用户常会说"我没研究 X""重点是 Y""明天改成 Z"。**直接重出完整日报**，不要只说"好的已改"，也不要只给改动的那半句 —— 用户要的是能直接复制的整段。
