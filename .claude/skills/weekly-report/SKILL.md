# Weekly Report（学习周报）

把用户这一周记在 `wiki/` 里的笔记，压缩成**一段中文周报**，直接在对话里给出。

## 周报 ≠ 七份日报拼起来

这是本 skill 唯一真正的难点。日报回答「今天干了啥」，周报要回答的是**「这周推进到哪了」**：

| | 日报 | 周报 |
|---|---|---|
| 视角 | 逐项流水账 | 主线 + 支线 |
| 时间 | 一天内的顺序 | **跨天的连贯性**——哪几天在攻同一件事 |
| 细节 | 点到函数名 | 点到**模块 / 主题**，函数名只留最关键的两三个 |
| 增量 | 今天新增了什么 | **这周比上周多会了什么**，有没有形成体系 |

写之前先问自己：这一周有没有**一条主线**？（比如「SGLang 源码从调度循环一路读到硬件底座」）
有就先说主线，剩下的归为支线；确实没有主线（几件事互不相干）就如实并列，别硬编故事。

## 铁律

1. **绝不写文件。** 不建周报文件、不改 `index.md`、不追加 `log.md`。唯一产物是对话里那段话。
2. **只写用户真学过的。** 和日报同一条底线，见下面的「反臆造」。周报跨度长、细节记不清，**更容易脑补**，要更克制。

## 步骤

### 1. 拉一周的汇总

```bash
bash .claude/skills/daily-report/scripts/collect_diff.sh "<vault根>" --days 7 --digest
```

脚本（与 daily-report 共用）给三块，正好对应周报要写的三件事：

| 输出块 | 用来判断 |
|---|---|
| **【一】按文件净新增行数** | 谁是主线（几百行）、谁是顺带（几十行）、哪些是本周**新建**的文章（★ 标记） |
| **【二】按天动过哪些笔记** | **连贯性**——同一篇连着三天出现 = 攻坚；只出现一天 = 单点 |
| **【三】本期新增章节标题** | 学了什么的主要线索，比正文更适合周报的粒度 |

用户说「上周」而不是「这周」，或要指定周期，换 `--since`：

```bash
bash .claude/skills/daily-report/scripts/collect_diff.sh "<vault根>" --since 2026-08-03 --digest
```

**退出码**：`0` 有改动往下走；`1` 该范围内无改动 → **别猜**，问用户；`2` 环境错误 → 报错。

### 2. 需要细节时再下钻

digest 只给标题。某篇是本周主线、光看标题写不出实质内容时，对**那一篇**取全文：

```bash
bash .claude/skills/daily-report/scripts/collect_diff.sh "<vault根>" --days 7 2>&1 | sed -n '/--- 文件：wiki\/学习整理\/SGlang.md ---/,/^--- 文件：/p'
```

**别一上来就拉一周全量**——那是几十万字符，白烧上下文。先看 digest，缺什么补什么，通常只需下钻一到两篇。

### 3. 判断主线与支线

- **主线**：净新增行数最多、且在【二】里**跨多天出现**的那一到两篇。
- **支线**：行数中等，或只在某一天集中出现。
- **噪声，一律跳过**：
  - `wiki/index.md` —— 索引条目，只说明某篇动过
  - `wiki/log.md` —— **我自己写的操作日志，绝不能当成用户的学习成果**
  - 净新增 0 行 / 个位数行的文件（改错别字、补链接）
- 脚本已经给这两个文件打了「噪声」标注，照做。

### 4. 写周报

**长度**：6–10 句。默认一整段；本周确实有 3 条以上互不相干的线时，可以用 2–4 个短条目，每条一句话。**不要**写小标题、不要三级列表、不要表格。

**结构**（固定顺序）：
1. **主线**：这周主要在推什么，推到哪一步了（这是周报的骨架，占一半篇幅）
2. **主线的具体展开**：点到模块 / 章节名，最多留两三个最关键的函数名或概念
3. **支线**：用「另外」「顺带」带过，一两句
4. **本周新建的文章**（★ 标记的）：如果有，点一句「整理出了 X 这篇」
5. **下周计划**：见下

**语气**：和日报一致——平铺直叙的第一人称流水账。不用「深入探索」「收获颇丰」「体系化提升」这类总结腔。
周报最容易滑向空话，**判断标准是：每一句都能对应到笔记里的具体内容**，做不到就删掉。

### 5. 下周的计划

按优先级取：
1. 用户在本轮对话里说了下周干什么 → 照写
2. 笔记里有明确的「待办 / 下一步 / TODO / 存疑」 → 用它（本周的存疑项是最好的素材）
3. 都没有 → 从本周主线的自然延续推一个，**并在周报正文外面说明这句是推的**，让用户好改

## 反臆造（周报的头号风险）

用户对准确度要求很高——他曾明确纠正过「我并没有研究 KV 缓存部分，只是知道了 RadixCache 这个数据结构」。

**深度必须如实**：

| 笔记里的痕迹 | 周报里该怎么说 |
|---|---|
| 单篇几百行、多天连续推进、有自己的分析 | 「主要在啃 X」「把 X 从头读到了 Y」 |
| 几十行、集中在一天 | 「另外过了一遍 X」 |
| 只有标题、几行列举 | 「顺带认识了 X」，或干脆不写 |

周报特有的两个坑，**尤其注意**：

- **别把「写了很多字」当成「学得很深」。** 有些行数来自我整理时补的背景，不是用户自己啃的。
  拿不准时，看【二】的跨天分布：**连着几天动同一篇 = 真在攻；一天写完 = 可能是一次性整理**。
- **别硬凑主线。** 这周要是就是散的，如实写「这周比较散，主要是 A 和 B 两块」，比编一条假主线强得多。

其余同日报：别把「知道名字」写成「研究了」，别替用户扩写他没写的东西，拿不准**按轻的写**然后在周报外面问一句。

## 输出格式

- 周报正文用 **blockquote**（`>`）包起来，方便整段复制。
- 正文之外可以补一两句说明：比如「下周计划是我推的」「X 我按『顺带』写了，如果你其实钻得挺深就告诉我」。
- 说明不要长，别喧宾夺主。

## 用户追改时

用户常会说「这周重点不是 X」「Y 才是主线」「下周改成 Z」。**直接重出完整周报**，不要只说「好的已改」，也不要只给改动的那半句——用户要的是能直接复制的整段。
