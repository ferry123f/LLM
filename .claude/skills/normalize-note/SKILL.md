# Normalize Note（笔记加工）

把一篇粗糙、常常不完整的笔记，加工成 vault 内精修文章的水准。**范本参照**：
- 内容加工方式 → `wiki/学习整理/SGlang.md`（由手写半成品整理而来：修笔误、补结构、加版本说明、双向回链）。
- 成品排版水准 → `wiki/deepseek/DeepSeek-V3 架构与低成本高效训练.md`（`# 标题` → `> 一句话` → `## 分节` → 表格/代码/公式 → 双链齐全）。

## 何时触发

用户说"整理""补充""完善""规范化""润色"并指向某篇 wiki 文章时。若没指明文件，先问是哪一篇。

## 优先级（本 skill 的核心取向）

**内容 > 格式。** 用户的笔记往往是不完整的草稿，价值在于被补全和校正，而不只是排好看。

### 第一优先：内容加工（主）
- **补全**：笔记里点到未展开、明显缺失的关键信息，主动补充完整（如某命令缺常用参数、某概念缺前提、流程缺一步）。
- **纠错**：修正明显笔误（拼写、变量名、函数名）、事实错误、过时说法。像 SGLang 那次修 `rece_requests → recv_requests`。
- **结构化**：把散乱内容按逻辑重组，抽出小节、表格、对照关系；用户后续扩充的零散内容一并纳入。
- **说明**：需要背景/版本/前提才成立的内容，补一句免责或说明（如"以下基于 xxx 版本"）。

### 第二优先：格式规范（辅）
- 补 `# 标题` + `> 一句话` 摘要；用 `##/###` 分节。
- 命令/代码/配置包进 ```` ```lang ```` 代码块；并列转列表，对照转表格。
- 补 `[[双链]]`（vault 内已有文章）与 `#标签`；文末补 `## See Also`。

## 安全底线（放开内容的同时必须守住）

1. **raw/ 永不改** —— 只读。发现 raw 有错，在 wiki 文章里标 `> ⚠️ source contains error: ...`，绝不改 raw。
2. **改动透明，不臆造** —— 补充和纠正要有依据（通用常识/官方文档/上下文可推断）。**拿不准的不硬改**：存疑处标 `> ⚠️ 存疑：...` 或行内 `（?）`，在完成汇报里单列，交用户定夺。宁可标注也不臆测。
3. **重大改动可追溯** —— 纠正了错误、补了成段内容，在 `log.md` 里写清改了什么、依据是什么。
4. **保留用户原意** —— 补充是"帮他把话说完"，不是"替他改主张"。用户的观点、选型、结论若无明显错误，不推翻。

## 收尾（遵守 CLAUDE.md 级联约定）

- **更新 `wiki/index.md`**：改这篇文章的条目（链接 + 一句话摘要 + `Updated: <今天>`）。
- **追加 `wiki/log.md`**：
  ```
  ## [YYYY-MM-DD] normalize | <文章标题>
  - 内容：补充 xxx / 纠正 xxx（依据 xxx）
  - 格式：分节重构 / 补双链 / 补标签
  - 存疑：<留给用户确认的点，若有>
  ```
- 日期用今天的日期（见 currentDate）。

## 完成后向用户汇报（分层，让用户一眼看清风险）
- **内容改动**（重点）：补了什么、改了什么、依据是什么。
- **存疑/待确认**：我拿不准、没敢硬改、标了 `⚠️` 的地方 —— 让用户重点看这里。
- **格式改动**：一句话带过即可。
- 新增的 `[[占位链接]]`（值得未来建独立页的概念）。
