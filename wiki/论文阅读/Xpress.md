# xPress: Parallel Refinement for Diffusion Drafters in Speculative Decoding

- **论文**：[xPress: Parallel Refinement for Diffusion Drafters in Speculative Decoding](https://arxiv.org/abs/2608.02438)
- **作者**：Zheng Wang, Davis Wertheimer, Yu Chin Fabian Lim, Mudhakar Srivatsa, Raghu K. Ganti, Minjia Zhang, Naigang Wang（UIUC + IBM）
- **出处**：arXiv:2608.02438v1, 2026-08
- **核心结论**：Qwen3-8B + dFlash block-16 drafter 上，接受长度平均 **+30%**（最高 +56%），端到端吞吐平均 **1.3×**（最高 1.7×）。

**两个创新点不是并列关系，是「制造问题」和「解决问题」的关系**：

```
问题：扩散 drafter 的分布是"模糊"的，草稿被提前拒绝
  ↓
创新点一：加一个极轻的因果 refiner，在已有候选里重排序
  ↓
但它制造了死结：算位置 k 必须先知道位置 k 之前的结果
  ↓
创新点二：用 Jacobi 并行迭代解开死结
  ↓
结果：接受长度 +30%，吞吐 1.3×
```

---

## 一、问题：不是选错，是分布本身模糊

### 机制

块扩散 drafter（dFlash）**一次双向前向填满整个 block**，产出每个位置的分布：

```
q_k(x_k | c)        ← 只条件于已验证上下文 c，不含块内前缀
```

而 target 验证时用的是真正的条件分布 `p(x_k | c, x_{<k})`，逐个从左到右核对。

### 为什么必然出错

当正确的下一个 token 依赖前缀时，drafter 只有一个分布，只能给**各支路的加权平均**。

上下文「I bought ___ ___ ___」，pos1 是限定词、pos3 是名词，单复数必须一致。设 drafter 在 pos1 的边缘分布是 `a: 0.58 / two: 0.42`：

| pos3 的分布 | car | cars | 其他 |
|---|---|---|---|
| target \| x1 = "a" | 0.85 | 0.05 | 0.10 |
| target \| x1 = "two" | 0.05 | 0.85 | 0.10 |
| **drafter 边缘（看不到 x1）** | **0.51** | **0.39** | **0.10** |

（`0.85×0.58 + 0.05×0.42 = 0.514`，`0.05×0.58 + 0.85×0.42 = 0.386`）

**边缘分布 = 对所有可能前缀求期望 → 必然被抹平。**

### 代价

```
接受率_k = 1 − TV(q_k, p_k^target) = 1 − ½‖q_k − p_k^target‖₁
```

代入上表：`1 − ½(0.34 + 0.34) ≈ 0.66`。

**反直觉的一点**：drafter 的 argmax 仍然是 `car`（0.51 > 0.39），**token 选对了**——但它给出的**分布**离 target 很远，即使选对也有约 1/3 概率被拒。

这也解释了为什么 **T=1 采样下增益更大**：采样从分布里抽，分布错了就会抽错。

### 为什么可解

关键前提：**正确 token 通常已在 drafter 的 top-k 候选里**。

所以问题不是"重新预测"，而是**在已有候选集内重新分配概率质量**。

## 二、创新点一：因果 refiner

> 论文 contribution 1：「Causal dependency injection at near-zero cost」

### 硬约束决定了唯一形式

drafter 的隐状态 `h` 是那**一次**双向前向算出来的、**固定不变**。没法让它"再算一遍但条件于前缀"——那等于退回自回归。

所以唯一能动的是 logits 上的**加性偏置**：

```
ℓ_k = s_k + δ_k          s_k 是 drafter 原始分数，δ_k 是要学的修正量
```

要起因果作用，偏置必须依赖前缀：

```
δ_k = R_θ(h_{1:B}, x_{0:B−1})_k     且要求 δ_k 只依赖 x_{<k}
```

论文列了四条必须同时满足的约束：

| 约束 | 含义 | 排除掉的设计 |
|---|---|---|
| **轻量** | 必须极小 | 再堆一个 transformer 层 |
| **因果** | 条件于**实际采样**的前缀 | 位置编码、无条件 bias |
| **有 drafter 依据** | 利用 drafter 已算出的隐状态 | 只看 token id（DSpark） |
| **低开销** | 不能退回串行左到右 | 串行递归（Domino 的 GRU） |

### 位置 k 需要什么信息

| 需要知道 | 对应输入 | 是免费的吗 |
|---|---|---|
| 前一个 token 是什么 | `x_{k−1}` | ❌ 需查 embedding |
| 本位置处于什么语义状态 | `h_k`（位置隐状态） | ✅ drafter 已算过 |
| 这块的全局语境 | `g`（全块均值） | ✅ drafter 已算过 |

`g` 不违反因果——它完全由固定的 `h` 算出，**不含任何采样 token 的信息**。

### 五个环节

#### ① Fuse

```
a_k = W_in [ W_h h_k ‖ W_g g ‖ W_e[x_{k−1}] ]
```

| 符号 | 是什么 | 本例取值 | 算出来 |
|---|---|---|---|
| `W_h h_k` | `h_k` 是位置 k 的隐状态（3 个数）；`W_h` 是 2×3 的表，降成 2 个 | `[0.5, -0.2, 0.8]` | `[0.40, -0.60]` |
| `W_g g` | `g` 是全块所有 `h` 的平均（3 个数）；`W_g` 也是 2×3 的表 | `[0.2, 0.17, 0.23]` | `[0.22, 0.20]` |
| `W_e[x_{k−1}]` | `x_{k−1}` 是**前一个 token 的编号**；`W_e` 是「编号→数」的表，取一行 | 取「cars」那行 | `[0.70, 0.20]` |
| `‖` | 中括号里的竖线 = 三段**首尾拼接** | — | 6 个数 |
| `W_in` | 2×6 的表，把 6 个数压回 2 个 | — | **`a₃ = [0.45, 0.22]`** |

> 此时 `a₃` 里**只含 `x₂ = "cars"` 的信息**，位置 3 完全不知道 `x₁` 是什么。**这就是下一步 Mix 的存在理由。**

#### ② Mix —— 因果性在这里产生

```
c_k = a_k + Σ_{j<k} L_{k,j} a_j
```

| 符号 | 是什么 | 本例取值 |
|---|---|---|
| `a_k` | 位置 k **自己**的值，系数固定为 1 | `a₃ = [0.45, 0.22]` |
| `Σ_{j<k}` | 求和号：把 `j = 1 … k−1` 各项**加起来** | `k=3` → 累加 `j=1,2` |
| `L_{k,j}` | `L` 表的**第 k 行第 j 列**那个权重。`L` **每个通道各一张** | ch1: `0.3, 0.4`；ch2: `0.6, 0.1` |
| `a_j` | 位置 j **自己**的值 | `a₁=[0.10,0.50]`、`a₂=[0.30,0.10]` |

展开并分通道代入：

```
c₃ = a₃ + L₃,₁·a₁ + L₃,₂·a₂

通道1：0.45 + 0.3×0.10 + 0.4×0.30 = 0.45 + 0.03 + 0.12 = 0.60
通道2：0.22 + 0.6×0.50 + 0.1×0.10 = 0.22 + 0.30 + 0.01 = 0.53
→  c₃ = [0.60, 0.53]
```

`L` 这张表长这样（右上角全 0 = "严格下三角"）：

```
        j=1  j=2  j=3          j=1  j=2  j=3
k=1      0    0    0    k=1      0    0    0
k=2     0.5   0    0    k=2     0.2   0    0
k=3     0.3  0.4   0    k=3     0.6  0.1   0
   ↑ 通道1的 L⁽¹⁾           ↑ 通道2的 L⁽²⁾
```

- **为什么产生因果**：`a₁` 装着 `x₀`、`a₂` 装着 `x₁`。位置 3 按权重把它们加进来，`c₃` 里就有完整前缀了。
- **为什么必须严格下三角**：位置 3 只用到 `L` 第 3 行中 `j≤3` 的格子；`j>3` 全是 0——**永远借不到未来位置的信息**。
- **混合的是"位置"而非"通道"**：张量 `A ∈ R^{r×B}`，Mix 对**每个通道单独**施加一个 `B×B` 矩阵，通道间不混合 → depthwise 操作，参数量 `O(rB²)`。若 `L` 只依赖位置差 `k−j`（Toeplitz），就退化成 **kernel size = B 的因果 depthwise 1d 卷积**。
- **为什么不用卷积/注意力**：卷积核长固定、覆盖全前缀需 kernel=B 反而更大；注意力要算 score、更贵且引入稀疏访问复杂度。B=16 的块尺度下，固定 `O(rB²)` 三角矩阵够用**且能预计算折叠**。

#### ③ Trans —— 唯一的非线性

```
z_k = c_k + W_2 σ(W_1 c_k)
```

| 符号 | 是什么 | 本例取值 | 算出来 |
|---|---|---|---|
| `W_1 c_k` | `W_1` 是 4×2 的表，把 2 个数**升**到 4 个 | `[0.60, 0.53]` | `[0.60, 0.53, 1.13, 0.07]` |
| `σ` | 逐元素 `max(0, x)`（ReLU） | 本例无负数 | 不变 |
| `W_2 σ(·)` | `W_2` 是 2×4 的表，把 4 个数**降**回 2 个 | — | `[0.685, 0.738]` |
| `+ c_k` | **残差连接**：把原值加回来，防信息丢失 | — | **`z₃ = [1.285, 1.268]`** |

**为什么必须有它**：Fuse 和 Mix **都是纯线性的**。只有这两步，整个 refiner 对输入的映射就是线性的，表达力太弱。

#### ④ Read

```
δ_k = W_r z_k
```

| 符号 | 是什么 | 本例取值 |
|---|---|---|
| `z_k` | 上一步输出 | `[1.285, 1.268]` |
| `W_r` | 4×2 的表（**4 个词 × 2 个数**），每行给一个词打分 | — |
| `δ_k` | 每个词拿到的**加减分** | **`{car:+1.919, cars:+0.372, is:+0.132, are:+0.255}`** |

> `W_e` 和 `W_r` 是**一对**（入口/出口），也是整套结构里唯一逃不出低秩空间的两个矩阵。

#### ⑤ Correct

```
ℓ_k = s_k + δ_k
```

| 词 | `s₃`（drafter 原分） | `δ₃`（refiner 修正） | `ℓ₃`（最终） |
|---|---|---|---|
| car | 1.80 | **+1.919** | **3.719 ← 最大** |
| cars | **2.10 ← 原最大** | +0.372 | 2.472 |
| is | 0.70 | +0.132 | 0.832 |
| are | 0.90 | +0.255 | 1.155 |

**argmax 从「cars」变成「car」——修正成功。**

> **refiner 不重新预测，只在 drafter 已有的候选里把分数调整到正确的那一个上。**

#### Mix 与 Trans 的分工

| | Mix | Trans |
|---|---|---|
| **跨位置吗** | ✅ 跨（沿位置轴混合） | ❌ 不跨（每位置独立算） |
| **线性吗** | ✅ 纯线性 | ❌ 有非线性 |
| **负责** | **位置间的信息流动** | **位置内部的表示加工** |

"**线性跨位置 + 非线性不跨位置**"是轻量网络的经典组合（类比深度可分离卷积 + 逐点卷积）：既让位置间信息自由流动，又保持整条路径可折叠。

### 为什么叫 "near-zero cost"

全 refiner **只有两处引入新信息**，其余全是变换：

| 阶段 | 引入的信息 | 是新算的吗 |
|---|---|---|
| Fuse 的 `W_e[x_{k−1}]` | **采样 token**（唯一入口） | ✅ 查一次 embedding |
| Mix 的三角矩阵 `L` | **因果结构**（唯一入口） | ✅ 需要新参数 |
| Fuse 的 `W_h h_k`、`W_g g` | drafter 隐状态 | ❌ **free** |
| Trans / Read | 只是变换 | ❌ 参数极小 |

再加一条工程优化：**Fuse 和 Mix 都是线性的，可折叠成预计算算子**：

```
c_k = Σ_{j≤k} M_{k,j} ã_j ,   ã_j = [W_h h_j ‖ W_g g ‖ W_e[x_{j−1}]]
```

`M` 只算一次，此后**每轮迭代 fuse–mix 只需一次 matmul**。这是 ~75 µs/轮的前提。

另外，**只加不换**（`ℓ_k = s_k + δ_k`）意味着即使 refiner 训崩了，最坏 `δ_k ≈ 0`，**退化回原始 dFlash，不会更差**。

## 三、创新点二：Jacobi 并行迭代

> 论文 contribution 2：「Parallel refinement」

### 为什么必须提出它

**这是全文最关键的一处逻辑。**

创新点一让 `δ_k` 依赖前缀 `x_{<k}`——这是准确性的来源。但它同时把自己逼进了死循环：

```
y_k = argmax_v [ s_k + R_θ(h, y_{0:B−1})_k ]_v
```

| 符号 | 是什么 | 已知还是未知 |
|---|---|---|
| `h_{1:B}` | drafter 隐状态 | ✅ 已知（迭代中固定） |
| `s_{1:B}` | drafter 原始分数 | ✅ 已知 |
| `y_{0:B−1}` | **块内所有 token 猜测** | ❌ **未知——这正是要求的东西** |
| `R_θ(h, y)_k` | refiner 给位置 k 的偏置 | ❌ 依赖未知的 `y` |

**左边是 `y_k`（未知），右边的 `R_θ` 里也含着一整套 `y`（同样未知）。**

所以这**不是一条"代入就能算"的公式，而是一个方程**。这就是必须引入迭代的根本原因。

论文 4.2 节原文承认了这点：

> "the refiner **naturally supports autoregressive generation. However, this left-to-right generation process pays an additional B−1-step loop cost**"

注意论文用的词是 "**naturally**"——**串行才是它最顺手的用法**，Jacobi 是刻意绕开串行的努力。

### 三条出路

| 出路 | 做法 | 准确吗 | 快吗 | 成本 |
|---|---|---|---|---|
| **串行左到右** | 先定 `x₁`，再定 `x₂`… | ✅ 准确 | ❌ B−1 步 | ~600 µs |
| **只跑一轮** | 拿种子直接当前缀 | ❌ 读到旧值 | ✅ 一次前向 | ~75 µs |
| **Jacobi 迭代** | 全块跑 K 轮 | ✅ 收敛到串行同一解 | ✅ 每轮并行 | **4 轮 ~379 µs** |

**关键算术**：若采纳串行，refiner 成本 ~600 µs。而它要打败的 baseline——**Markov head 的 15 步串行解码恰好是 601 µs**。

> **不做 Jacobi，创新点一就白干了。**

所以 **Jacobi 不是"性能优化"，而是"可行性条件"**。

### 具体操作：快照 + 冻结

```
Y^{(0)} = (argmax_v s_{k,v})_{k=1}^B          ← 种子：drafter 自己的一次性预测

for j = 0 … K−1:
    (δ_1,…,δ_B) ← Refiner(Y^{(j)}, {h_k}, g)   ← 一次并行前向
    y_k^{(j+1)} = argmax_v (s_k + δ_k)_v ,  k=1…B   ← 所有位置同时更新
    if Y^{(j+1)} == Y^{(j)}: break             ← 到达不动点，停
```

**关键机制是三件事**：

1. 每轮开始时，把上一轮结果冻结成一份**只读快照** `Y^{(j)}`
2. 本轮所有位置**都只读这份快照，谁都不改写它**
3. **写入统一发生在本轮全部算完之后**

于是各位置的读取窗口是：

| 位置 | 本轮读快照的哪几格 | 哪些格子本轮会被改 |
|---|---|---|
| 位置1 | `x₀` | 都不会 |
| 位置2 | `x₀, x₁` | 都不会 |
| 位置3 | `x₀, x₁, x₂` | 都不会 |

**没有一格会在本轮被改写**，所以位置2 不需要等位置1，可以立刻读那份已经躺在内存里的旧值。**没有任何位置在等"另一个位置本轮的输出"——这就是并行成立的充分理由。**

### 与串行的唯一差别

| | 算 pos_k 时读哪版前缀 | 信息传播 | 每轮成本 |
|---|---|---|---|
| **串行（Gauss-Seidel）** | 刚更新过的 `y_{<k}^new` | **立即** | 只算 1 个位置 |
| **Jacobi** | 上一轮的 `y_{<k}^old` | **延迟一轮** | 同时算全部 B 个位置 |

- **代价**：信息每轮只能右传一位 → 最坏 B 轮收敛
- **回报**：每轮所有位置**互不依赖** → 一轮一次前向

**为什么不能选"读新值"**：位置2 读"本轮位置1 的新值"，意味着位置2 必须排在位置1 之后执行——**这是串行依赖链，硬件上根本没法并行**。

> **并行性和"读新值"在硬件层面是互斥的。** Jacobi 主动放弃"读新值"换"所有位置同时算"，再用多轮把延迟传播欠的轮数补回来。

### 迭代推演

上下文「The two ___ ___ ___」，三个位置分别是名词、动词、形容词：

```
pos1:  car 0.51 / cars 0.49                    ← 不依赖前缀
pos2 | car → is 0.95     | cars → are 0.95      ← 单复数一致
pos3 | is  → red 0.90    | are  → blue 0.90     ← 语义搭配
```

drafter 的边缘分布把 pos2、pos3 抹平成几乎持平。T=1 采样时容易抽出不自洽的组合，假设种子抽到 `Y^{(0)} = [cars, are, blue]`：

| 轮次 | pos1 | pos2 | pos3 | 说明 |
|---|---|---|---|---|
| 种子 `Y⁽⁰⁾` | cars | are | blue | 三个位置互不自洽 |
| 第 1 轮 | **car** | are | blue | pos1 只看锚点→修正；pos2 读到的仍是旧 `cars`，没改对 |
| 第 2 轮 | car | **is** | blue | pos2 读到修正后的 `car`→变 is；pos3 读到的仍是旧 `are` |
| 第 3 轮 | car | is | **red** | pos3 读到修正后的 `is`→变 red；全部自洽 |
| 第 4 轮 | car | is | red | 无变化 → 到达不动点，退出 |

**注意第 1 轮 pos2 为什么没改对**：它读到的是**上一轮的** `cars`（`pos2|cars → are`）。这就是"延迟一轮传播"的具体体现。串行会当轮改对（省轮数），Jacobi 则一轮算完所有位置（省前向次数）。

### 三个关键问题

**Q1：怎么知道对不对？**

**迭代过程中 refiner 根本不检查 target——它只检查"自己变没变"。**

| | 内层：refiner 的 Jacobi 迭代 | 外层：target 的验证 |
|---|---|---|
| **判据** | 输出有没有变化：`Y⁽ʲ⁺¹⁾ == Y⁽ʲ⁾ ?` | 分布是否与 target 一致：`1 − TV` |
| **问 target 吗** | **全程不问** | 这才是真正的判据 |
| **归属** | xPress 引入 | 投机解码原有流程 |

**Q2：为什么"没变化"就等于"对了"？**

更新规则是 `y_k ← argmax p_k(v | y_{<k}, h, g)`。若所有位置算出的值都与快照相同，则每个 k 都有 `y_k = argmax p_k(v | y_{<k}, h, g)`——**意味着每个位置在给定自己前缀的前提下都是最优选择，这正是自回归解码的定义**。

所以"不再变化"不是"猜不下去了"，而是"**每个位置都与自己的前缀自洽了**"。

**Q3：为什么一定收敛、为什么 K 很小？**

**定理 1**：依赖结构严格因果 + `h, g` 迭代间固定 → 可证

```
y_k^{(j)} = y*_k   对所有 j ≥ k 成立
```

**直觉**：每轮把"已正确前缀"向右推进至少一位，稳定性从锚点向右传播。最坏 B 轮达到唯一不动点。

**为什么实际 K 很小**：**位置 k 本轮能算对，当且仅当快照的前 k−1 位已正确。** 种子质量高时，很多位置**读旧值就已正确** → 正确前缀**跳跃式增长**，而非每轮只 +1。

论文实测 **K ≈ 6 就足以匹配 15 步串行解码的接受长度**。

### 成本账

| | 位置数/次 | 单次耗时 | 总耗时 |
|---|---|---|---|
| Markov head（串行 15 步） | 1 | ~40 µs | **601 µs** |
| xPress（4 轮并行） | 16 | ~95 µs | **379 µs** |

**并行前向做 16 倍的位置数，成本只有单位置的约 2.4 倍**——因为 refiner 极轻（r=256，线性部分已折叠成单次 matmul），单位置前向时 GPU 严重欠载，多塞 15 个位置几乎不增加成本。

> **并行的收益不是"收敛更快"，而是"同样的收敛过程用了更少的墙钟时间"。**

## 四、两个创新点之间的逻辑

```
                    ┌─────────────────────────────────┐
                    │  目标：让草稿分布接近 target     │
                    └───────────────┬─────────────────┘
                                    ↓
              ┌─────────────────────────────────────────┐
              │  创新点一：因果 refiner                  │
              │  让 δ_k 依赖前缀 x_{<k}                 │
              │  → 准确性的来源                          │
              └───────────────┬─────────────────────────┘
                              ↓
                ┌─────────────────────────────┐
                │  但它制造了死结：            │
                │  x_{<k} 本身是待求量         │
                │  → 未知数出现在等式两边      │
                │  → 这是方程，不是公式        │
                └───────────────┬─────────────┘
                                ↓
              ┌─────────────────────────────────────────┐
              │  创新点二：Jacobi 并行迭代               │
              │  快照 + 冻结，K 轮收敛到串行同一不动点   │
              │  → 可行性的条件                          │
              └───────────────┬─────────────────────────┘
                              ↓
                    ┌─────────────────────┐
                    │  接受长度 +30%      │
                    │  吞吐 1.3×          │
                    └─────────────────────┘
```

### 互相成就

| 贡献 | 提供什么 |
|---|---|
| **创新点一**（极轻的 refiner） | 让"并行前向几乎免费"成立——16 个位置的成本仅比单位置贵 2.4 倍 |
| **创新点二**（Jacobi） | 才能用"多跑几轮"换"每轮全并行" |

**如果 refiner 很重，这个交换就不划算了。** 这就是标题里 "near-zero cost" 与 "parallel refinement" 的内在联系。

> **只提创新点一 = 一个跑不动的好想法。只提创新点二 = 没有需要求解的对象。两者必须成对出现。**

## 五、结果

### 与 DSpark 的对比（论文 Table 1，同一训练配方，受控）

| | dFlash 原始 | Markov head | **xPress** |
|---|---|---|---|
| **T=0 平均 τ** | 6.25 | 7.64 | **8.02** |
| **T=0 平均吞吐** | 4.9× | 6.1× | **6.2×** |
| **T=1 平均 τ** | 4.94 | 6.62 | **6.97** |
| **T=1 平均吞吐** | 3.6× | 4.7× | **5.3×** |

xPress **在每个 benchmark、每个温度下都优于 Markov head**，采样时（T=1）优势更明显。

**精度-延迟的解耦**（xPress 的优势所在）：

| K | xPress 延迟 | Markov head | 接受长度对比 |
|---|---|---|---|
| 1 | 150 µs | 601 µs（固定） | xPress 较低 |
| **4** | **379 µs** | 601 µs | **xPress 已全面追平或超过** |
| 6 | 530 µs | 601 µs | 达到精度平台 |
| 8 | 681 µs | 601 µs | 两者交叉 |

> **K=4 时 xPress 已更准且更便宜（379 vs 601 µs，快 1.6×）——双占优。**

而 Markov head 的精度上限**被结构锁死**：只能看 1 个 token，再花多少时间也突破不了。

**一句话**：Markov head 修的是"相邻两 token 的局部冲突"，xPress 修的是"整块的因果结构"。

### 整体结果

Qwen3-8B + dFlash block-16，7 个 benchmark（数学 / 代码 / 对话）：

| | T=0 | T=1 |
|---|---|---|
| 接受长度 τ | +18~56% | +19~58% |
| 平均 τ | 6.25 → **8.02** | 4.94 → **6.97** |
| 平均吞吐 | 4.9× → **6.2×**（+1.29×） | 3.6× → **5.3×**（+1.46×） |
| 最高单点 | GSM8K **1.70×** | AIME25 1.50× |

- **T=1 增益更大**：dFlash 在 T=1 下从 4.9× 崩到 3.6×，xPress 维持 5.3×。说明修正**恰好在 base drafter 最弱的场景最有用**。
- **对话（MT-Bench）最难的领域仍有增益**（1.36× / 1.39×）。
- **vLLM 大 batch（bs=32）优势保持**：绝对吞吐每个格子都最高，相对 dFlash 的优势**基本与 batch 无关**（稳定 1.2–1.4×）。
