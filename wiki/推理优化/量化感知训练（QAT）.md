# 量化感知训练（QAT）

> 一句话：QAT 在训练前向里插入**伪量化**让权重提前适应量化误差，是精度补救梯子（RTN → 校准 PTQ → QAT → 蒸馏级配方）的最后一级。在 Qwen3-0.6B 上的两阶段实验实证：**int4 及以上校准 PTQ（GPTQ/AWQ）已够用，int3 附近 QAT 不可替代（PTQ 崩溃而 QAT ≈ 原模型），int2 以下连 QAT 也救不动**；vLLM 实测同时表明——量化的精度收益与速度收益是两笔独立的账，小模型上 W4A16 只省显存不提速。

## 一、量化基础：把浮点映射到离散格点

以 FP32 → INT8 为例，量化的核心思想是把浮点区间的参数**线性映射**到低比特整数的离散空间：

$$r = S\,(q - z)$$

其中 $r$ 是 FP32 浮点值，$q$ 是 INT8 量化值，$S$ 是缩放因子（scale），$z$ 是零点（zero-point）。两个参数由映射区间决定：

$$S = \frac{r_{max} - r_{min}}{q_{max} - q_{min}} \qquad z = q_{min} - \frac{r_{min}}{S}$$

![[quant-fp32-int8-symmetric-mapping.png]]

几个立刻派生出来的设计选择：

- **对称 vs 非对称**：对称量化取 $r_{max} = -r_{min} = \max|x|$，此时 $z=0$，乘法里少一项，kernel 更快；非对称能更贴合不对称分布。权重通常对称、激活常非对称。
- **粒度**：一个 scale 罩多大范围——per-tensor（整个张量一个）→ per-channel（每输出通道一个）→ **per-group**（每 32/64/128 个权重一个）。粒度越细损伤越小、元数据越多。**LLM 权重量化的工程标配是 per-group（g=128 最常见）**，而且 group 大小对精度的影响可以和量化算法本身同量级——对比实验必须锁定同一 group size。

### W×A× 记号：分清"低比特存储"和"低比特计算"

量化方案的命名格式是 **W（权重位宽）+ A（激活位宽）**。这个记号背后藏着一个容易误解的关键机制：

| 方案 | 显存里存什么 | 矩阵乘用什么执行 | 每次乘前要反量化吗 |
|---|---|---|---|
| **W4A16**（GPTQ/AWQ/本实验） | int4 权重 + bf16 激活 | **bf16** Tensor Core | **要**：int4 权重当场解回 bf16 |
| **W8A8**（SmoothQuant / fp8） | int8/fp8 权重 + 激活 | **int8/fp8** Tensor Core | 不用（输出 rescale 一次即可） |

原因很朴素：Tensor Core 只支持**同类型相乘**，不存在 int4 × bf16 的运算单元。W4A16 只量化权重，恰好制造了类型不一致，所以每一层、每个 token 的矩阵乘都要走"搬 int4 → 寄存器里反量化成 bf16 → bf16 矩阵乘"的循环——Marlin 这类 kernel 的全部工程价值就是把中间那步做快、和搬运重叠，但它只能被摊薄，不能被消除。W8A8 免反量化，代价是激活也得量化，而激活有系统性离群值通道，精度难题转移到了那一侧（SmoothQuant 为此而生）。

由此分出两条工程路线：

- **算力路线（W8A8）**：矩阵乘本身用低比特算力执行，吞吐翻倍。fp8 在 H100+ 上近乎免费，是当下部署的总体主流；A100 无 fp8 单元，只有 int8 TensorCore 可走。
- **显存路线（W4A16）**：只压权重体积和搬运字节，计算照旧。是"单卡装下大模型 / 小 batch 提 decode 速度"场景的主流。**QAT 的战场在这条路线的低比特端。**

## 二、精度补救的梯子：RTN → 校准 PTQ → QAT

量化必然损伤精度，补救手段按成本排成一架梯子，**能便宜解决就不上贵的**：

1. **RTN（round-to-nearest）**——训练后量化（PTQ）的最朴素形态：不看数据，逐 group 算 scale 直接四舍五入。免费。
2. **校准 PTQ（GPTQ / AWQ）**——仍不训练，但拿一两百条校准数据"看一看"，据此聪明地定量化参数：GPTQ 逐层做误差补偿（量化一列、把误差摊给未量化的列），AWQ 按激活幅度事前保护重要通道（对照见 [[LLM分布式]] 的量化一节）。便宜：0.6B 几分钟出一个模型。
3. **QAT（量化感知训练）**——在训练前向里插入**伪量化**（fake quantize）：权重每次前向都被"量化再反量化"，模拟舍入误差，但底下存储仍是 bf16；反向用 **STE（直通估计器）** 让梯度穿过不可导的 round。权重在梯度更新中逐渐移动到"即使被量化也不太伤"的位置，训毕 convert 成真量化权重。

```python
class FakeQuantSTE(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, scale, zp, qmin, qmax):
        q = torch.clamp(torch.round(x / scale) + zp, qmin, qmax)
        return (q - zp) * scale          # 量化再反量化，dtype 仍是 bf16
    @staticmethod
    def backward(ctx, g):
        return g, None, None, None, None  # STE：round 导数处处为 0，梯度直通
```

QAT 的实践形态是**微调**而非从头训练：学习率压到预训练的 1/10~1/100（本实验 2e-5）——目标是让权重适应量化，不是重学任务。

于是自然产生两个必须用实验回答的问题：**这架梯子每一级到底值多少？爬到哪一级该停？**——这就是下面两个实验各自的任务。

## 三、实验一：位宽扫描——找 QAT 的不可替代区间

### 背景与目的

教程都说"QAT 精度比 PTQ 好"，但没人说好多少、什么时候值得。QAT 要花训练成本，如果 PTQ 已经够用它就是浪费；反过来 PTQ 一旦失效，QAT 就是唯一选项。所以第一个实验的目标：**沿位宽维度扫出一条曲线，定位"PTQ 失效、QAT 仍存活"的边界**。边界只能用相邻点定位——单测任何一个位宽都会得出片面结论，故扫 int8/4/3/2 全位宽。

### 实验设置

| 模型   | Qwen3-0.6B（bf16），单张 A100-80G                                                                                                                   |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据   | wikitext-2：train 训练（约 250 万 token，切 1024 长块），test 测 PPL                                                                                        |
| 量化方案 | 对称 · per-group(32) · RTN 家族，int8/4/3/2 只动位宽一个变量                                                                                                |
| 量化范围 | 仅 Transformer 内 Linear 权重；embedding / lm_head / norm 保持 bf16（Qwen3-0.6B tie_word_embeddings=True，lm_head 与 embedding 共享存储，动它会连带损坏 embedding 表） |
| 训练   | 500 步 · lr 2e-5 · bs 8 · 梯度裁剪 1.0 · cosine 退火                                                                                                  |
| 指标   | 测试集困惑度 PPL（越低越好），辅以定性生成样例                                                                                                                      |
| 工具链  | torch 2.9 + torchao 0.16（QATConfig 伪量化）                                                                                                        |

数据特意**不用指令/对话数据**：要测的是"量化损伤了多少语言能力"，训练分布必须贴近预训练分布，否则测量被行为漂移污染。

### 关键设计：五臂对照

设计上最要紧的一点：**QAT 是个复合动作**——它既"在数据上训练了"（这件事自己就涨分，与量化无关），又"感知了量化"。要把第二件事的贡献单独称出来，必须让每次比较只差一个变量。两个开关（训练 × 量化）张成 2×2，QAT 作为第五个点落在"既训练又量化"的格子里：

| | 不量化 | 量化 |
|---|---|---|
| **不训练** | fp16（尺子零点） | ptq（量化裸损伤） |
| **训练 500 步** | ft（训练本身的功劳） | ptq_ft（先训完再量化）＋ **qat**（边训边感知） |

ptq_ft 与 qat 同数据、同步数、同学习率、同量化方案，唯一区别是**训练时知不知道自己将被量化**——**唯一干净的 QAT 收益读数是 qat vs ptq_ft**。若拿 qat 直接对 ptq，差值里混着微调功劳（本实验中高达约 10 个 PPL），必然高估 QAT。ptq_ft 同时也是工程上的真实备选：同样有 500 步预算、要交付量化模型，你的选项就是"正常训完再量化"和"带感知训"这两个。

### 结果

| 位宽 | ptq | ptq_ft | qat | QAT 净收益（ptq_ft − qat） |
|---|---|---|---|---|
| fp16 | 23.875 | — | — | — |
| ft | — | 14.127 | — | — |
| int8 | 27.932 | 18.686 | 16.297 | +2.39 |
| int4 | 29.575 | 19.775 | 16.932 | +2.84 |
| **int3** | **64.698** | 47.233 | **24.003** | **+23.23** |
| int2 | 841012 | 826790 | 15246 | 无意义 |

> 数字有效范围注记：本表用 torchao 0.16 纯 Python 路径量化，其 int8/int4 的**绝对**损伤偏大（实验二用与实现无关的手写 fp32-scale 量化器复核：int8 权重量化实际近乎无损，23.85 vs 基线 23.88）。臂间**相对**对比不受影响——所有臂共用同一实现。这条注记本身就是一个方法论结论：**量化评测前先验证量化实现，工具库的数值路径也会引入自己的误差。**

三段式读法：

- **int8 / int4**：损伤 4.6~5.6，QAT 追回约一半。收益真实但有限。
- **int3——悬崖出现，全场题眼**。PTQ 的 PPL 炸到 64.7，生成退化成复读机（"expansion and the role of the... expansion and the role of the..."）；QAT 拉回 **24.0，与原模型 23.9 几乎持平**，生成通顺。**PTQ 失效而 QAT 仍能交付原模型级质量——QAT 不可替代的区间从这里开始。**
- **int2——谁也没活下来**。QAT 把 PPL 从 84 万压到 1.5 万（55 倍），但 1.5 万仍是乱码——那是两个失效模型之间的比较，不构成可用性。训练 loss 在 8~10 之间震荡 500 步不收敛：4 个量化等级装不下语言，这不是步数问题而是配方问题。要让 2bit 活需要重型手段：长程训练 + 知识蒸馏、三值化（BitNet 类 {-1,0,1}）、甚至从头训练——这正是 2bit 至今是研究前沿而非工程选项的原因。

### 小结

QAT 的价值区间不在主流位宽（int8/int4 收益太小），而在**校准手段也压不住的低比特端（int3 附近）**；再往下它自己也不够。同时，一次训练在评测域上带来的涨分（≈10 PPL）远大于多数量化方案间的差距——**看任何量化评测先问对照组：baseline 是 RTN 还是 GPTQ？训没训？同预算吗？**

## 四、实验二：int4 主战场——主流方案同台与推理实测

### 动机

实验一回答了"QAT 何时不可替代"，但 int3-RTN 没有人真的部署；工程主流是 **int4 + 校准 PTQ（GPTQ/AWQ，g=128）**。所以把坐标轴从"位宽"换成"方案"，钉死在 W4A16-g128 上回答真实的选型问题：**免费的 RTN、便宜的 GPTQ/AWQ、贵的 QAT，到底差多少？** 并补上实验一没测的另半边：这些方案在真实推理引擎里跑多快。

### 设置

- 所有方案统一 W4A16 · per-group(128)；GPTQ/AWQ 用 llmcompressor 产出（compressed-tensors 格式，vLLM 原生加载）。
- **校准数据与 QAT 训练数据同源**（同一批 wikitext train 块，256 条 × 1024 token）——校准臂和训练臂看同样的数据才公平。
- RTN / QAT 臂改用**手写 fp32-scale 对称 per-group 量化器**，与任何库实现解耦；QAT 训练仍用 torchao 伪量化，convert 后用同一手写量化器落地。
- 性能实测：vLLM 0.11.2 离线引擎，`vllm bench throughput`（200 条 ShareGPT，并发吞吐）与 `vllm bench latency`（batch=1，128 入 / 256 出，单流延迟）。

### 质量结果

| 方案 | 成本 | PPL | 相对 fp16 |
|---|---|---|---|
| fp16 基线 | — | 23.875 | — |
| RTN | 免费 | 33.873 | +9.99 |
| AWQ | 校准 256 条 | 28.241 | +4.37 |
| GPTQ | 校准 256 条 | 27.060 | +3.19 |
| RTN + ft | 训练 500 步 | 20.787 | −3.09 † |
| QAT | 训练 500 步 | 19.192 | −4.68 † |

† 低于 fp16 是 500 步域内微调的功劳（纯微调 ft = 14.1），不是"量化免费午餐"。

两对干净读数（各自内部同预算，互相**不可对撞**——一边免费一边花了 500 步训练）：

- **校准的价值** = GPTQ vs RTN = 追回 6.8 / 10.0 ≈ **67% 的损伤，零训练白拿**。这就是生产界普遍用 GPTQ/AWQ 的原因。AWQ 略逊于 GPTQ，在 0.6B 上正常——小模型上 AWQ 的 scale 搬移不如 GPTQ 的逐层误差补偿精细。
- **量化感知训练的价值** = QAT vs RTN+ft = 净赚 **1.6**（g32 时为 2.8），前提是愿意付 500 步。

工程翻译：**不愿训练，GPTQ 是免费午餐里最好的一顿；愿意在目标域训 500 步，顺手做 QAT 是最优解。**

另一个值得记录的观察：QAT / RTN+ft 的生成样例出现轻度复读（500 步单一域微调的过拟合迹象），GPTQ 的样例反而更多样——**PPL 不是唯一的尺子**，选型应配生成质量抽查。

### vLLM 实测：有 kernel 也没提速

vLLM 加载 GPTQ/AWQ 模型，确认命中生产级 `MarlinLinearKernel`——然而在 0.6B 上，int4 两种负载下**全面慢于 fp16**：

| 模型 | 吞吐 req/s（200 并发） | 输出 tok/s | batch=1 延迟 |
|---|---|---|---|
| fp16 | **38.8** | **8664** | **0.682 s** |
| GPTQ int4 | 24.9（−36%） | 5561 | 0.782 s（+15%） |
| AWQ int4 | 24.9（−36%） | 5564 | 0.775 s（+14%） |

带宽账解释一切（decode 为 memory-bound 的背景见 [[LLM推理的GPU硬件基础]]）：0.6B 的可量化权重仅 ~0.9GB（bf16），A100 2TB/s 带宽下每 token 权重搬运 ~0.45ms，只占实测每 token 2.7ms 的 **<20%**——量化把它压到 1/4，理论上限也只省 ~13%，而每次矩阵乘的反量化开销（见 §一 W4A16 机制）与未量化的 lm_head 把节省吃光倒贴。吞吐模式下瓶颈在算力，反量化是纯增量计算，故 −36%。

**W4A16 提速的前提是"权重搬运主导每 token 耗时"**——模型越大、batch 越小越成立。0.6B 处在"量化只为省显存"的区间；7B 级以上权重搬运占比 >70%，此表预期反转。**"临界尺寸"是可复用的判断工具：先算权重搬运占比，再决定量化是否为了速度。**

## 五、总结论：一套可复用的选型方法

1. **速度账先行**：权重字节数 ÷ 显存带宽 = 每 token 搬运时间，与实测每 token 时间一比。占比高（大模型、小 batch）→ W4A16 真提速；占比低（小模型或大 batch 吞吐场景）→ 量化只省显存，甚至倒贴。要算力翻倍走 W8A8/fp8 路线（激活量化的精度难题另算）。
2. **精度梯子逐级爬，爬到够用就停**：int8 无损伤可救；int4 到 GPTQ/AWQ 为止（零训练追回 ~67%）；**int3 附近校准也失效，QAT 不可替代**；int2 以下 QAT 也不够，需蒸馏级配方。
3. **QAT 的适用判据一句话**：不是"某个位宽该用 QAT"，而是**"免费和便宜的手段（RTN → 校准）失效了没有"**——QAT 永远是梯子的最后一级。此外它的另一潜在战场是 W4A4（激活也量化）——校准同样难压激活离群值的地方。

适用范围：以上数字测自 Qwen3-0.6B + wikitext-2 + 500 步预算；小模型对量化更敏感，悬崖位置与提速临界尺寸都会随模型规模移动，换模型应复测。

## 附：复现

实验脚本：`qat_common.py`（量化配置与 PPL 评估）、`run_sweep.py`（实验一位宽扫描）、`phase2_quantize.py` / `phase2_quality.py` / `phase2_bench.sh`（实验二）。环境：torch 2.9.0+cu129 · torchao 0.16.0 · llmcompressor 0.8.1 · vLLM 0.11.2。

```bash
# 实验一：位宽扫描（含 5 轮训练，~1.5h，nohup 落盘）
nohup python -u run_sweep.py --model /models/qwen3-0.6b \
  --bits 8 4 3 2 --steps 500 --bs 8 > sweep.log 2>&1 &
tail -f sweep.log          # Ctrl+C 只退出查看，不影响训练
pgrep -f run_sweep         # 存活检查；中途停止用 pkill -f run_sweep

# 实验二：产出 GPTQ/AWQ → 质量表 → vLLM 性能

nohup python -u phase2_quality.py --model /models/qwen3-0.6b > phase2.log 2>&1 &
bash phase2_bench.sh
```
