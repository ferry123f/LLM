# DeepSeek-V3：MLA + MoE 架构与 5.576M 美元的高效训练

> 一句话：DeepSeek-V3 用 **MLA 低秩注意力** + **DeepSeekMoE** + **无辅助损失负载均衡** + **MTP 多 Token 预测**，配合 **FP8 训练**和 **DualPipe** 流水线，把 671B（激活 37B）大模型的完整训练成本压到 **2.788M H800 GPU 时 / 约 557.6 万美元**，性能追平 GPT-4o 与 Claude-3.5-Sonnet，是当时最强开源模型。

## 核心论点

大模型的训练成本和推理效率是规模化的核心矛盾。DeepSeek-V3 的答案是"**架构省显存、工程省算力、蒸馏省数据**"三条腿：

- 架构上继承 V2 的 **MLA** 和 **DeepSeekMoE**，再叠加两项首创——**无辅助损失的负载均衡策略**和**多 Token 预测（MTP）训练目标**；
- 工程上首次在超大规模上验证 **FP8 混合精度训练**可行，配合 **DualPipe** 近乎零开销的跨节点通信，算力利用率极高；
- 训练极其稳定：全程**无不可恢复的 loss spike，无一次回滚**。

最终 14.8T token 的完整训练只花 **2.788M H800 GPU 时**（约 557.6 万美元，按 $2/GPU 时估算）。

## 三大架构支柱

V3 的基本架构（论文 Figure 2）——上半部是 **DeepSeekMoE**（共享专家 + Router 选 Top-K 路由专家），下半部是 **MLA**（输入先压成 latent 向量，再分出带 RoPE 的位置分支，只缓存打阴影的部分）：

![[deepseek-v3-arch-mla-moe.png]]

### 1. MLA：多头潜在注意力（省 KV 缓存）

- 对 Key/Value 做**低秩联合压缩**：KV 压缩维 512、Query 压缩维 1536，推理时只缓存压缩后的潜在向量，KV 缓存大幅缩小。
- **解耦 RoPE**：位置编码走单独的小维度分支，避免和压缩表示纠缠。
- 效果：显存占用远小于标准 MHA，性能不降。

**核心公式：** 先把输入 $\mathbf{h}_t$ 压成一个低维潜在向量 $\mathbf{c}_t^{KV}$（维度 $d_c \ll d_h n_h$），推理时**只缓存这个 $\mathbf{c}_t^{KV}$ 和一路共享的 RoPE 键 $\mathbf{k}_t^R$**，用时再上投影还原出各头的 K/V：

$$\mathbf{c}_t^{KV} = W^{DKV}\,\mathbf{h}_t \qquad(\text{下投影压缩})$$
$$\mathbf{k}_{t}^{C} = W^{UK}\,\mathbf{c}_t^{KV},\qquad \mathbf{v}_{t}^{C} = W^{UV}\,\mathbf{c}_t^{KV}\qquad(\text{用时上投影还原})$$
$$\mathbf{k}_{t,i} = [\,\mathbf{k}_{t,i}^{C};\ \mathbf{k}_t^{R}\,],\qquad \mathbf{k}_t^{R}=\mathrm{RoPE}(W^{KR}\mathbf{h}_t)\qquad(\text{拼接解耦的位置分支})$$

> 直觉：标准注意力要缓存每个头完整的 K、V；MLA 只存一份被压缩了几十倍的 $\mathbf{c}_t^{KV}$，这正是"省 KV 缓存"的来源。

### 2. DeepSeekMoE + 无辅助损失负载均衡（首创）

- **细粒度专家 + 共享专家隔离**：1 个共享专家（所有 Token 都过）+ 256 个路由专家（每 Token 选 8 个）。
- **无辅助损失负载均衡（关键创新）**：传统 MoE 靠辅助损失强制均衡，但会损害性能。V3 改为给每个专家的路由亲和度加一个**可动态调整的偏置项**——过载就调低、欠载就调高偏置，**只影响路由选择、不进入门控权重**。由此几乎不靠辅助损失就实现均衡，性能更好。
- 仅保留一个权重极小（α=0.0001）的**序列级均衡损失**兜底，防止单条序列内极端不均。
- **节点受限路由**（每 Token ≤4 节点）+ 全程**不丢弃任何 Token**。

**核心公式：** 关键在于路由用的门控值 $g$ 里加了一个**可动态调整的偏置 $b_i$**——选专家时用"亲和度 + 偏置"排序，但真正的加权求和**只用原始亲和度 $s_{i,t}$**，所以偏置只改"选谁"、不污染"权重"：

$$g_{i,t} = \begin{cases} s_{i,t}, & s_{i,t}+b_i \in \operatorname{Top\text{-}}K_r(\{s_{j,t}+b_j\}) \\ 0, & \text{否则} \end{cases}$$

每步结束后，按各专家的负载更新偏置：**过载的专家调低 $b_i$、欠载的调高**，从而无需辅助损失就把流量均匀摊开：

$$b_i \leftarrow b_i - \gamma\,\mathrm{sign}(\text{load}_i - \overline{\text{load}})$$

### 3. MTP：多 Token 预测（训练目标）

- 训练时额外预测未来 **D=1** 个 Token。与 Meta 的并行预测不同，V3 用**串行 MTP 模块**并保留完整因果链。
- 每个 MTP 模块与主模型**共享 embedding 和输出头**，只额外带一个 Transformer 块 + 投影矩阵，开销小。
- **推理时可直接丢弃** MTP 模块（主模型独立工作）；也可复用它做**投机解码（speculative decoding）**——第二个 Token 接受率达 **85%–90%**，端到端 TPS 提升约 **1.8×**。

## 基础设施：让 FP8 训练在超大规模跑通

- **DualPipe 双向流水线**：重叠前向/反向的计算与通信，几乎消除流水线气泡，并把 EP 带来的 all-to-all 通信藏进计算里，实现近 1:1 的算通比。
- **高效跨节点 all-to-all 通信核**：吃满 InfiniBand（50GB/s）与 NVLink（160GB/s），warp 专门化，仅用约 20 个 SM 即可，用 PTX 指令自动调优 chunk 大小。
- **FP8 混合精度训练（大规模首次验证）**：
  - 细粒度量化——激活按 **1×128 tile**、权重按 **128×128 block** 分块量化，抑制异常值。
  - **提升累加精度**——每累加约 128 个元素就**搬到 CUDA Core 用 FP32 累加**，弥补 Tensor Core 累加位宽不足。
  - 全部张量用 **E4M3**、在线量化；缓存激活/通信用低精度。
  - 相对 BF16 基线，训练 loss 误差 **< 0.25%**。

论文 Figure 6——三个最重的矩阵乘 **Fprop（前向）/ Dgrad（激活反向）/ Wgrad（权重反向）走 FP8**，而累加、主权重、优化器状态保留 **FP32/BF16** 高精度，兼顾速度与稳定：

![[deepseek-v3-fp8-framework.png]]
- **显存优化**：重算 RMSNorm/MLA 上投影、EMA 放 CPU、MTP 与主模型共享 embedding/输出头——**全程不需要张量并行**。
- 集群：2048 张 H800，16 路 PP + 64 路 EP + ZeRO-1 DP。
- 还向硬件厂商提了建议：Tensor Core 需要更高累加精度、原生支持 tile/block 量化与在线量化、转置 GEMM 等。

## 预训练

- **14.8T token**，语料侧重数学与代码、扩展多语种。文档打包但不做跨样本注意力屏蔽；引入 0.1 比例的 **Fill-in-Middle（FIM）**。
- Tokenizer：128K 词表 BPE。
- 超参：AdamW，最大学习率 2.2×10⁻⁴，batch size 从 3072 渐增到 15360，最大序列长 4K。
- **长上下文两阶段扩展**：用 **YaRN** 把 4K → 32K → 128K，每阶段各 1000 步。128K 内 NIAH（大海捞针）几乎满分。
- 基座评测：多数基准上是**当时最强开源基座**，数学与代码尤其突出。

## 后训练

- **SFT**：1.5M 条指令覆盖多领域。推理类数据由 **DeepSeek-R1 蒸馏**生成（在准确率与简洁性之间平衡长 CoT）；非推理类来自 DeepSeek-V2.5 + 人工校验。
- **强化学习（GRPO）**：
  - **规则奖励**：数学/代码等有确定答案的用规则或编译器判分（如 LeetCode）。
  - **模型奖励**：自由形式任务用从 V3 SFT 检查点派生的奖励模型。
- **R1 推理蒸馏**：把 R1 的长链推理能力蒸进 V3，显著提升数学/代码，同时控制回复长度膨胀。

## 评测亮点

- **综合**：**最强开源模型**，整体追平 **GPT-4o-0513** 与 **Claude-3.5-Sonnet-1022**。
- 知识：MMLU 88.5、MMLU-Pro 75.9、MMLU-Redux 89.1、GPQA-Diamond 59.1。
- 数学：MATH-500 **90.2**、AIME 2024 39.2——开源数学 SOTA。
- 代码：Codeforces 百分位 51.6、SWE-bench Verified 42.0。
- 对话/开放：**Arena-Hard 85.5%**（首个在 Arena-Hard 超过 85% 的开源模型），AlpacaEval 2.0 70.0。
- 中文事实性（Chinese SimpleQA）超过 GPT-4o 与 Claude；但英文 SimpleQA 仍落后闭源。

## 局限与未来方向

- **部署单元偏大**：为效率推荐的最小部署单元较大，小团队可能吃不消。
- 端到端生成速度仍有提升空间。
- 未来：突破 Transformer 架构限制（趋向无限上下文）、持续提升数据质量与数量、加强深度推理、探索更全面的评测方法（避免过拟合固定基准）。坚持开源与长期主义。
